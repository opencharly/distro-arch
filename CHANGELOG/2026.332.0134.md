# 2026.332.0134 — fix(check-tmux-pod): give tmux-roundtrip its own timeout instead of the never-hang ceiling

## Summary

`Closes opencharly/distro-arch#75` — the canonical ceiling issue (#84 was its duplicate and is closed).

`check-tmux-pod`'s `tmux-roundtrip` check declares no `timeout:`, so it inherited the ~2-minute never-hang ceiling. The typed-terminal round-trip drives a detached pod through the agent channel and captures ordered evidence, which exceeds that ceiling on a cold host: the probe was **signalled mid-run** and reported **no exit status** (`probe killed by never-hang ceiling after 1m59.852s`), failing the bed regardless of the code under test.

This adds `timeout: 900s` — the same generous value the bed already declares for its other long host-orchestration step (`measured 2m51s`), so the check states its own deadline instead of inheriting the ceiling.

### Spike

**RCA claim:** the ceiling, not the probe's logic, is what fails the bed. Each candidate below was RUN on this same bed with the shipped-pin binary (`2026.331.2341`), with the per-step `timeout:` removed so the candidate carries the whole fix.

- **A. Declare an explicit `timeout:` on the step (WINNER).** Instrument: a run **at the failure boundary** — the plugin-view cache cleared so each of the probe's ~20 `charly` calls pays the cold-host resolve cost again, exactly the condition that motivated the fix. With `timeout: 900s` in place:

  **Works at the boundary**: the probe exceeded the never-hang ceiling and still completed with a real exit status, because the authored `timeout:` raised its bound to 930 s (sdk `kit/runner.go`: `ProbeNeverHang` returns `authored + 30s` when larger). The red arm at the same boundary is candidate B's run below, which is the same shape WITHOUT the per-step timeout: `[check-live] FAIL after 2m9.703s`, `probe killed by never-hang ceiling`, `bed_exit=2`.

  **Honest caveat, filed not hidden:** that same cold-cache run's REBUILD pass failed at `stage=deployment-ssh-grpc-tmux` (`exit=1`, `23 steps: 19 passed, 1 failed`) — the second occurrence of opencharly/charly#1314 (the SSH bootstrap hop intermittently returning no exit frame, direct or nested), which is unrelated to the timeout: the probe ran 3m, well inside the 930 s bound, and the failing stage is the agent channel's SSH hop. - **B. Raise the GLOBAL never-hang ceiling instead.** Instrument: `defaults.readiness.per_attempt: 15m` in the project (the global knob — `#Readiness.per_attempt`, `spec/schema/box.cue`), per-step `timeout:` removed:
