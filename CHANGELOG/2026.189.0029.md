# 2026.189.0029 — pin backend: libvirt on the arch-pacstrap VM entity

The `arch-pacstrap` VM entity carried no `backend:` pin, so `backend: auto`
silently fell back to QEMU under host load — creating the domain OUTSIDE
libvirt and failing every `libvirt:` RPC probe in the `check-arch-pacstrap-vm`
bed with "Domain not found" (surfaced by the concurrent bed roster; the sibling
`arch` entity already documents + pins against this exact fallback). Pinned
`backend: libvirt`. An R3 sweep confirmed every other probe-backed VM entity
(root charly-vm/k3s-vm, fedora-vm/web-vm, cachyos gpu VMs) is already pinned.
