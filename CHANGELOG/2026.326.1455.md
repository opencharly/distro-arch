# 2026.326.1455 — feat(boxes)!: aur is a routed builder, not a build format; arch-builder builds mise

## Summary

distro-arch's half of the unified builder mechanism (opencharly/sdk#608). A box's `build:` lists OS package formats; `aur` is a build-time manager, routed by the image's `builder:` map, so `arch-test` drops it.

- **`box/arch-test/charly.yml`** — `build: [pac]` (it was `[pac, aur]`). The box composes `arch-aur-test`, whose candy declares `distro.arch.aur`, and its `builder: aur: arch-builder` route is what makes the aur builder run.
- **`box/arch-builder/charly.yml`** — `produce:` gains `mise`. An arch box composing a mise candy routes to this box, and validation refused the route while it did not declare mise (measured: `builder.mise references "arch-builder" which does not declare builds: [mise]`). The mise stage needs only curl and tar, which this box has.
- **Four skills** — `arch`, `arch-test`, `arch-aur-test`, `arch-pac-test` now say what is true: no `build: [pac, aur]` opt-in, the route is what selects the builder, and a builder that cannot run fails the build naming the candy.

**A mixed state is silent, and is filed.** Building the same box with an OLDER `plugin-builder-aur` (the released ref) copies the payload and installs nothing, and `check box` reports four `yay` failures — measured. opencharly/sdk#615 records it: the pre-pass asks whether a builder can run, never whether it speaks the current reply contract, so a stale plugin must be made loud.
