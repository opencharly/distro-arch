## Root cause

The org reusable workflow this dispatcher calls declares job-level permissions:

```yaml
# opencharly/.github/.github/workflows/tag-on-merge.yml
jobs:
  tag-and-changelog:
    permissions:
      contents: write
      pull-requests: read
```

A caller that sets an explicit `permissions:` block makes **every scope it does not list `none`**,
and a reusable workflow may not request more than its caller's ceiling — so the call is rejected
before any job starts, which is exactly `startup_failure` with no job to inspect. This repo's
dispatcher granted only:

```yaml
permissions:
  contents: write        # pull-requests is therefore `none`
```

Repos that tag successfully today (`marketplace`, `charly`) grant `pull-requests: read`. That is
the difference, and the diff of this PR is `+  pull-requests: read` plus the rest of the current
dispatcher.

The dispatcher here was also **two revisions behind**: it still used the `schedule` cron trigger
whose delivery the org measured at 21–44 minute gaps with no SLA, instead of the event-driven
`workflow_run` + `push` form with the bounded `wait-for-merge` readiness probe.
