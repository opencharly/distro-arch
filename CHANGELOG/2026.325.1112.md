# 2026.325.1112 — fix(arch-skills): drop the copy step; kind:skill installs the owned skills

## Summary

Closes opencharly/distro-arch#73. The `arch-skills` carrier drops its `copy: .agents/skills` step, because charly now installs the skills a composed candy owns (opencharly/sdk#598).

That step was resolved against the carrier's own staged directory, so it could never reach the repo-root bodies (opencharly/sdk#444). Every remote import of distro-arch failed with `"/.agents/skills": not found`: this repo's own `arch.arch`, opencharly/pod-kde-cstream, opencharly/pod-kde-vnc (opencharly/pod-kde-vnc#3), and the CachyOS whisper box (opencharly/opencharly#1204).

Now `kind:skill` installs the body of every skill an image's composed candies own, at the image user's `~/.agents/skills/<name>/`, through one `COPY` of the owned content. It carries the same set whole in the `ai.opencharly.skill` label. The carrier keeps its eight `skill:` routing nodes and its `skill-bodies-installed` ADE `check:`, which proves the bodies landed. Its header comment and `description:` now say whose install it is.

| file | change |
|---|---|
| `candy/arch-skills/charly.yml` | the `install-skill-tree` `run:` step deleted; header and `description:` rewritten |

**Order:** it needs a charly carrying the chain (opencharly/charly#1230, merged, tagged `v2026.325.1102`). Under an older charly, a carrier with no install step installs nothing, so this lands after that tag.
