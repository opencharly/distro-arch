# 2026.320.1359 — feat(arch)!: retire the non-CachyOS vscode demo bed and its image

## Summary

Retires `check-arch-vscode-pod` and the `vscode-test` image it was the only deploy definition of.

`vscode-test` was a VS Code direct-download install demo — neither charly's own machinery nor a
package build — so it is one of the nine `pod:`/`vm:` definitions the org's non-CachyOS retirement
deletes (opencharly/opencharly#1068). The distro-level bed goes with the image, per the operator's
decision that a dropped definition takes its now-bedless workload image with it.

**`layer-vscode` does NOT lose its live proof.** Verified before the deletion rather than assumed:
the candy is composed by the CachyOS `cachyos-gpu` box in `opencharly/distro-cachyos`, so its baked
checks still run on a live CachyOS container. Deleting this bed removes a *demo* composition, not the
candy's only gate.

**What stays, and why.** Every Arch bed that proves a charly surface is untouched: `check-arch-vm`
(VM deploy substrate), `check-tmux-pod` (the typed terminal channel), `check-agent-pod` +
`check-agent-live` (the agent control plane), and `check-arch-pacstrap-vm` (the pacstrap bootstrap
builder), together with the `arch` / `arch-pacstrap` fixtures they use.

**Nothing references the deleted pair.** Measured before the change: no repo references
`arch.vscode-test`, `arch.check-arch-vscode-pod`, or `base: vscode-test` anywhere in the org.
