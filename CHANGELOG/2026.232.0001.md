# 2026.232.0001 — align the auto-merge engine to the org-wide guarded canonical

The org-wide `auto-merge` engine (the corrected engine already live on this
repo's `main` since the previous cutover) gained one addition on the sdk
contract repo: `tag_ver()`, which mints sdk's Go-module tag form
`v0.<YYYYDDD>.<HHMM with all leading zeros stripped>` instead of the plain
`v<YYYY.DDD.HHMM>`. The guard is **inert on every non-sdk repo** (the
`REPO = opencharly/sdk` branch never fires), so this change is a
byte-identity alignment to the canonical engine — no behavior change on
distro-arch.

The corrected engine's guarantees, restated:

- **Merge only when ALL status checks are green** — `wait_all_settled()` +
  `verify_all_green()` run on the initial head and on the post-finalization
  revalidation head; only `success`/`skipped`/`neutral` check conclusions are
  accepted, and any non-green combined commit-status state blocks the merge.
- **CHANGELOG finalization at merge time** — the placeholder file is renamed
  to the merge-time CalVer (H1 rewrite + `auto-merge-finalized` marker) with
  `GITHUB_TOKEN`; the validator is re-run via the Actions API and waited on.
- **Native auto-merge** — `gh pr merge --squash --auto`; no direct-squash
  fallback.
- **Tag minted add-only on the merged HEAD** — the local-ref existence check
  replaced the broken 404-body guard.

Validated by the 102-assertion stub-`gh` harness (23 scenarios, incl. the
sdk tag-scheme guard) before the engine ever landed; the live run of this
workflow on `main` is the R10 gate.
