# 2026.229.1420 — declare source.distro on the cloud_image VM

in this repo, with no filename or tag collision.

`source.distro` selects three things about a guest that nothing else in the spec implies: its
package NAME (`openssh` vs `openssh-server`), its package MANAGER (`pacman -Sy --needed` vs the
`packages:` cloud-config key) and its sshd UNIT name (`sshd` vs `ssh`).

It used to be INFERRED from `base_user`, and only for `arch` and `alpine` — every other distro
fell through to Arch/Fedora conventions. So a Debian-family image that omitted it was rendered
`openssh` + `systemctl enable --now sshd`, a unit Debian and Ubuntu do not have, and with
cloud-init's deliberate `mask ssh.socket` that left a socket-activated sshd masked and never
started: the guest booted fully and served nothing.

That inference is deleted in opencharly/sdk#140. `spec.DistroSSHUnits[distro]` and
`spec.DistroInits[distro]` are now bare lookups in tables generated from
`schema/distro_vocab.cue` (opencharly/spec#35) with **no default**, so an absent distro no longer
silently means "Fedora conventions" — it means an empty unit name. Presence is enforced at author
time by the vm kind's own OpValidate capability, so this repo's cloud_image source
must state `arch` explicitly.

## Why this repo has to land before its consumers

Consumers pin this repo by tag. Their suites fail against the currently-pinned copy for exactly
this reason, so the tag minted on merge is what unblocks them.
