# 2026.264.0042 — feat(distros): own the arch-family skills in distro-arch

## Summary of changes

Move the seven arch-family `skill:` entities out of the
`opencharly/layer-charly-distros` concept aggregator and into this repo — the
repo that actually owns the artifacts they document:

| Skill | Documents |
|---|---|
| `arch` | `box/arch` base image |
| `arch-builder` | `box/arch-builder` |
| `arch-aur-test` | `candy/arch-aur-test` |
| `arch-pac-test` | `candy/arch-pac-test` |
| `arch-test` | `box/arch-test` |
| `arch-coder` | `box/arch-coder` |
| `charly-arch` | `box/charly-arch` |

Each entity is copied **verbatim** (identical `name`/`family`/`description`/
`content`), with `owner:` corrected from the aggregator's
`charly-distros`/`charly-coder` to each skill's own name — the convention every
single-candy repo already uses (`layer-chrome` owns `chrome` with
`owner: chrome`; `pod-ollama` owns `ollama` with `owner: ollama`).

## Change class

**Candy/box config** — `charly.yml` carries seven `skill:` entity fields, and the
rulebook's class table is explicit that "a YAML field is config". The required
gate is the config-class gate, not `documentation reviewed`. Tier:
**`analysed on a live system`** — the generator (the only consumer of a `skill:`
entity) ran live with retained output, and the config-class pre-flight was
proven to exercise the moved entities; a full fresh-rebuild R10 is not
applicable because a `skill:` entity is harness prose with no image or deploy
artifact for a bed to compose or fail on.

- **The gate that exercises the change:** `charly marketplace generate` +

## Wave / landing order (cross-repo cutover)

This PR is the PRODUCER of a three-PR wave. The other two cannot exist before
this merges (the marketplace pin must reference the CalVer tag this merge mints;
the aggregator deletion must follow that pin so the generation closure never
loses the skills). Fixed order, each PR titled exactly:

1. **this PR — `opencharly/distro-arch`**: `feat(distros): own the arch-family skills in distro-arch` (merge mints `v<CalVer>`).
2. **`opencharly/marketplace`**: `chore(refs): pin distro-arch:v<CalVer> + regenerate` — adds `@github.com/opencharly/distro-arch:v<CalVer>` to `candy/charly-marketplace/charly.yml`, regenerates; its drift gate proves the corpus is byte-identical.
3. **`opencharly/layer-charly-distros`**: `refactor(distros): drop the arch-family skills (moved to distro-arch)` — deletes the seven now-duplicated entities.

Between step 1 and step 3 the seven entities exist in both repos — the
unavoidable transient of a repo-split cutover across three independently-landing
repos (they cannot share one PR). It is bounded to this wave: steps 2 and 3 are
opened and landed immediately, and no further skill moves begin until step 3
merges. After step 3, `git grep` for each moved entity returns only the
aggregator's CHANGELOG history.
