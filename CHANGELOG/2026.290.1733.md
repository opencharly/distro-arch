# 2026.290.1733 — fix(arch): give the seven skill routing nodes the description and content the schema requires

## Summary

**This fixes a repo-wide blocker, not a cosmetic validation gap.** Seven skill routing nodes in `charly.yml` (`arch`, `arch-aur-test`, `arch-builder`, `arch-coder`, `arch-pac-test`, `arch-test`, `charly-arch`) carry `name`/`family`/`owner` only. `#SkillInput` requires **both** `description` and `content` to be non-empty, and the failure is not confined to `validate` — **project resolution fails on the first node**, so no bed in this repo could run at all:

```
distro-arch/charly.yml:doc0: node "arch-aur-test-skill": plugin kind:skill: plugin_input fails
  #SkillInput: #SkillInput.description: incomplete value !="" (and 1 more errors)
```

Found while advancing the GPU layer pins in `box/charly-arch` and `box/cuda-arch-builder`; that pin change is prepared and held locally, unsent, because this gate was red.

Both required fields are filled for all seven nodes, sourced from each node own **`.agents/skills/<name>/SKILL.md`** — the source of record for the prose — so **no text is invented**: the frontmatter `description:` becomes the node `description:` as a block scalar, and the body after the closing `---` becomes the node `content:`.

The same pass applies to the sibling repos; `opencharly/distro-cachyos` had it in eleven nodes across three files and it was fixed in `distro-cachyos#137`.
