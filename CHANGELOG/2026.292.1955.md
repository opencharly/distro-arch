# 2026.292.1955 — feat(skills): strip the seven inline `arch` skill bodies now that routing-only nodes validate

## Summary

Strips the seven inline `content:` bodies from this repo's `skill:` nodes, leaving each node with its routing metadata only (`name`, `family`, `owner`, `description`) and the relocated body under `.agents/skills/<name>/SKILL.md`.

The bodies were already moved by **#57** (`feat(skills): the seven arch skill bodies move to .agents/skills (W4)`). They came back in **#61** — *"give the seven skill routing nodes the description and content the schema requires"* — because the `#SkillInput` schema in the charly binary then used to validate the repo rejected a routing-only `skill:` node. That is no longer true: a current charly accepts routing-only nodes, and the CI validator has passed and merged two trees in this shape within the last two days (`distro-ubuntu#44`, `distro-omarchy#75` — both at `0` inline `content:` blocks, `validate / validate pass`).

So this is the strip that #61 had to reverse, re-applied against the schema that now applies.

Related: `#60` reports the `#SkillInput` rejection. That is a stale-binary symptom rather than a manifest defect — the same class as `opencharly/opencharly#515` — and this PR is the demonstration that the manifest shape it blocks now validates.
