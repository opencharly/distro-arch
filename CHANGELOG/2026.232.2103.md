# 2026.232.2103 — fix the CHANGELOG already-finalized guard
<!-- auto-merge-finalized: 2026.232.2103 -->

The engine's already-finalized check read the head's placeholder file and
grepped for the literal finalize-marker name. A placeholder whose prose
legitimately describes the merge-time finalize (naming that same phrase)
therefore matched the guard, the finalize was silently skipped, and the
release tag was minted at the author's placeholder stamp instead of the
merge-time stamp. Caught live on this repo's previous cutover (#16), where the
placeholder narrative described the marker: the engine skipped the finalize
and tagged `v2026.232.0001` (the placeholder) instead of a merge-time CalVer.
The tag and its changelog remain immutable history; this change prevents the
class.

The fix: the already-finalized check now requires the marker to carry the
file's **own** basename stamp — the exact form the finalize writes when it
renames the placeholder to the merge stamp (an HTML comment whose payload is
the marker name + `: ` + the merge stamp). Author prose describing the marker
as a concept cannot contain the stamp-suffixed form, so a genuine placeholder
is always finalized to the merge-time CalVer and tagged with the merge stamp.

Validated: the stub-gh harness extended with a regression scenario (placeholder
prose naming the marker) — **108 passed, 0 failed**.
